# 接入手册：sprite-frontend-developer

用户直接粘贴 [README 的白话 prompt](../README.md)，由 AI 完成接入。

## 接入当前项目

根据当前会话和项目情况判断客户端，沿用它支持的接入方式；不确定且影响接入时再查证或询问用户。

从同一明确版本读取 README 完整资源清单、[角色定义](../templates/agent.md)，默认接入以下四个完整、同级的 Skill 目录：

- [sprite-frontend-developer-ui](../skills/sprite-frontend-developer-ui/SKILL.md)：总流程、共享方法和完整模板。
- [sprite-frontend-developer-plan](../skills/sprite-frontend-developer-plan/SKILL.md)：规划阶段。
- [sprite-frontend-developer-implement](../skills/sprite-frontend-developer-implement/SKILL.md)：实现阶段。
- [sprite-frontend-developer-quality](../skills/sprite-frontend-developer-quality/SKILL.md)：验证阶段及专项参考。

每个阶段有自己的完整步骤，不能用跳转入口或摘要替代。保持四个目录在同一 Skill 根目录，共享 `references/` 和 `assets/` 留在 `sprite-frontend-developer-ui`，质量专项参考留在 quality 原目录。默认完整安装四个目录，执行时按需读取；单独使用指只执行当前阶段，不要求先执行其他阶段，不等于只复制当前阶段与共享目录。用户明确要求部分安装时，先沿全部本地引用递归核对依赖，包括共享目录中的阶段路由及下一阶段链接，说明实际需要的同级目录范围；本工作流这些引用相互连接，完整依赖范围为上述四个目录。尊重用户明确排除的资源并说明相应不可用入口，不能省略依赖后声称完整可用。用户明确只要职责定义时说明尚未带入执行能力。

网页来源先固定到完整提交，再读取该提交的全部资源；历史 `v0.2.0` 可明确选用，内容以该标签为准，不能把新阶段拼进旧版本冒充完整发布。本地未提交内容如实标注；取不到源文件就说明缺项，不自行编写替代品。

原样复制角色正文、Skill、工作流、模板和随附文件，保持资源名称与内部相对目录，只适配目标客户端必要的文件位置、格式和入口引用。专业内容不删改，项目已有规则和自定义继续保留。角色负责职责与清单，实际执行读取对应 Skill；接入本身不填写业务模板，也不建立安装登记。

## 资料和产物放哪里

资料来源仓库（host repo）与产物业务仓库可以不同，已明确的仓库直接沿用；尚未明确的仓库合并用白话问一次，允许稍后确定并先完成接入，实际使用时再补必需版本和文件。上游资料按真实路径读取。本角色生成的业务文档及附件统一保存在业务仓库 `docs/frontend-developer/`，可在角色目录下按功能分组，不另行选择散落位置。已有本职产物散落在其他位置时，先读取并保留有效内容，再迁入 `docs/frontend-developer/`，同步文内链接、其他引用及已有索引；遇到同名文件先比较并合并，避免覆盖用户内容。源码、测试、迁移、配置及构建输出保持工程原生目录，角色和 Skill 安装资源保持客户端目录。

本地资料直接使用。确需跨 Git 读取、固定版本或导出时，按 [bridge 接入手册](https://github.com/ai-sprites/artifact-bridge/blob/main/docs/installation.md)复用或补齐完整 Skill 并告知用户，无需另发安装指令；用户已拒绝或条件不足时说明限制。角色可以独立使用，业务留存见 [产物交接说明](artifact-handoff.md)。

## 已有内容与后续维护

沿用已有角色和 Skill 安装资源位置；相同内容直接复用，用户自定义保留，实质冲突只询问相关部分。更新完整采用同一版本，不因追加或更新删除未选资源。

旧版只有 `sprite-frontend-developer-ui` 和可选 quality 时，保留原名称，更新总入口与角色路由，补齐 plan、implement、quality 及共享参考。比较旧来源与当前安装的差异，把用户自定义保留或迁入对应阶段；有冲突只处理受影响文件，不直接覆盖。核对旧入口、相对引用及客户端加载位置，避免同时激活重复旧入口。移除只处理用户指定范围，保护自定义及仍被引用的文件；删除共享目录前核对仍使用它的阶段，不留下断链。

## 完成后告诉用户

核对四个 Skill 的实际文件、正文完整性、同级目录、共享依赖和相对引用，然后简明说明来源版本、保存位置与调用方式。按当前环境验证加载情况，区分“已保存”“已加载”和“已执行”。

需要用户亲自完成的步骤，按现场情况列成简短清单；没有就不加。只有聊天权限时可先在本会话使用，明确未写入项目及尚未完成的部分。
