# Phase 2 — IMPLEMENT：实现与修复

**输入：**已确认请求、等价计划或明确的修复目标，以及相关代码、测试和真实契约。

**输出：**工程目录中的代码与对应测试、真实改动和初步检查记录；完整验证由质量阶段承接。

执行前读取 [职责与授权边界](../sprite-frontend-developer-ui/references/boundaries.md)，沿用已有决定和授权；本阶段可单独运行，共享参考随安装保留，不要求先执行其他阶段。
所需入口或共享参考缺失时，从 [本角色仓库](https://github.com/ai-sprites/frontend-developer) 的同一明确版本补齐完整目录，保留自定义；取不到则说明缺项，继续有依据的独立部分。

## 1. 接住已确认要求

读取请求或现有计划、目标页面代码、测试、真实契约及适用技术约定。没有独立计划但范围和预期足够明确时直接实施；缺项只暂停受影响部分。按 [本职工作方法](../sprite-frontend-developer-ui/references/workflow.md) 选择现有技术和普通本职依赖，保留来源及版本，不暗改固定版本或已确认范围。

编辑前核对工作区已有修改；多人涉及共享契约、公共库、根配置、CI 或公共测试时沿用或明确单一编辑者及顺序。纯评审只给基于实际差异的结论，不因进入本阶段自行实施。

## 2. 实现界面、布局与可操作性

读取 [复用与布局](../sprite-frontend-developer-ui/references/reuse-layout.md)，使用已验证的组件 API、项目样式/主题和真实资产，优先组合现有能力。按本次需求处理长文案、翻译、日期金额格式、窄视口换行/折叠/滚动，保持 DOM 阅读和操作顺序。

使用语义元素、可读标签、焦点可见性与必要替代文字；新增自定义控件才核对它的完整键盘与焦点规则。审阅备注放说明或标注层，不进入产品 DOM；页面不得加入猜测内容、无功能按钮或“待确认”横幅。

## 3. 接通状态、表单与真实接口

读取 [状态与表单](../sprite-frontend-developer-ui/references/states-forms.md)，按真实请求响应、错误和分页契约实现。URL、服务数据、局部输入和临时界面各有归属，避免重复派生状态；缓存更新和失效沿用项目方法。

区分首次加载、已有内容刷新、空结果和失败。取消旧请求或阻止过期响应覆盖新结果，清理副作用；提交失败保留有效输入，字段错误可关联且不只依赖颜色。超时后结果未知、重复提交和安全重试按服务真实语义处理，不凭禁用按钮声称后端已防重，客户端校验或隐藏控件不替代服务端授权。

共享契约确需变化时遵守主源、编辑分工与当前授权；后端服务、数据库和后端部署仅在请求明确扩展范围内修改。

## 4. 补相关测试，核对实际差异

执行 [工程纪律](../sprite-frontend-developer-ui/references/engineering.md)：清楚表达输入、状态、副作用与失败语义，约束重试、取消和超时，保护敏感信息；依赖和优化以实际需要及测量为依据。

行为变化新增或更新测试，覆盖改变结果和重要保留行为，不为无行为变化写镜像测试。运行已核实的项目检查，涉及视觉实际渲染，记录真实命令与结果；初步检查不能冒充未执行的浏览器、键盘或读屏验证。审查差异中的越界、噪声、秘密、兼容破坏和无谓复杂度，保护用户修改。

## 5. 交给验证与交接

更新已有计划或任务的实际状态，按 [交付与留存](../sprite-frontend-developer-ui/references/delivery.md) 记录变更、理由、采用决定、初步检查与未验证项；需要功能交接时使用完整 [实施说明模板](../sprite-frontend-developer-ui/assets/templates/implementation-notes.md)。交付真实代码和文档路径，不只链接模板。

## 完成条件与下一阶段

- 当前授权范围内的最小完整改动及相关测试已完成，或明确具体受阻部分。
- 代码、实际契约与必要旧行为一致，已审查真实差异并记录初步检查。
- 交接包含真实文件、变化理由和待验证行为。

完整开发任务继续 [Quality](../sprite-frontend-developer-quality/SKILL.md)，依当前改动选择检查并完成真实验证。用户明确只要代码/草稿或不运行时，标明未验证；质量阶段不能因此声称通过。
