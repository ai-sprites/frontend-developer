# Phase 3 — QUALITY：验证与交接

**输入：**已有实现或失败、实际被测版本、已确认验收与契约、可用环境及测试。

**输出：**实际执行结果、可复现问题、未覆盖项与有成立范围的验证结论。

执行前读取 [职责与授权边界](../sprite-frontend-developer-ui/references/boundaries.md)，沿用已有决定和授权；本阶段可单独运行，共享参考随安装保留，不要求先执行其他阶段。
所需入口或共享参考缺失时，从 [本角色仓库](https://github.com/ai-sprites/frontend-developer) 的同一明确版本补齐完整目录，保留自定义；取不到则说明缺项，继续有依据的独立部分。

## 1. 确认验证对象和证据范围

读取请求、验收、已确认设计、真实差异、接口主源及现有测试；按 [验证依据](../sprite-frontend-developer-ui/references/workflow.md#验证依据) 记录版本、浏览器/视口、环境、关键输入和检查授权。已有来源和授权直接沿用，缺少预期或访问只暂停依赖部分；单独验证不要求先执行 Plan 或 Implement。

## 2. 按用户结果选择检查

读 [行为检查](references/behavior.md)，将本次变化和重要保留行为对应到最贴近风险的层次：纯计算、组件交互、导航或跨页面浏览器路径。表单与异步页面选择相关的成功、服务拒绝、延迟/乱序、空结果、重复操作及恢复分支，不为小改动搭建新测试平台或跑无关组合。

涉及真实退化、较大依赖、图片、渲染或错误恢复时，再读 [性能与错误](references/performance-errors.md)。使用项目已有目标；没有目标时报告测量条件与观察值，不新设发布门槛。

## 3. 实际执行并保留证据

核实项目命令后运行相关测试和静态检查。行为变化补充有价值的测试，缺陷测试尽可能证明修复前失败、修复后恢复。按支持范围实际渲染受影响页面，观察溢出、遮挡、布局跳动及操作完成情况；以键盘走输入、提交、错误修正和关闭返回，核对标签、阅读顺序与焦点。

静态检查、自动化浏览器、人工操作、自动扫描和读屏分别记录；没有实际读屏结果就标未验证。使用合成数据，截图与快照不得夹带真实用户数据，断言快照及测试代码保留工程目录。

性能比较记录原有基线、环境和操作，优化后同条件复查；实验环境与真实用户分布分别说明，开发环境一次结果不用于承诺生产体验。对相关取消、超时、断网、服务端错误和重试观察输入保留、恢复及副作用；注入、会话、凭据或遥测变化只核对受影响的既有安全边界。

## 4. 诊断失败并复验

保存首次失败、精确步骤、预期/实际和环境，区分测试问题、产品缺陷、缺失决定与环境阻碍。偶发失败检查异步等待、资源清理和环境；在当前测试授权内修复有效测试，不靠延长等待、弱化断言或删除用例获得通过。修复后重跑受影响检查与相关回归，单纯重复重跑不算修复。

有本职产品修复授权时交给 Implement 处理后返回验证；只有检查授权时保留可复现缺陷和具体影响，不自行改变产品行为。记录未覆盖浏览器、视口、辅助技术及原因。

## 5. 形成有范围的结论

按 [验证记录与留存](../sprite-frontend-developer-ui/references/delivery.md#验证记录) 将验收/风险、精确命令或操作、逐项结果、证据、问题复现、未覆盖原因、残余风险和总体通过/失败/阻碍判定写入已有说明，或 `docs/frontend-developer/<feature-id>/frontend-verification.md`；一次简单检查可在回复记录。结论只覆盖实际证据成立的范围。

## 验证授权边界

按当前授权执行检查并新增或修正有行为价值的测试，保持确定性和有效断言；发现产品缺陷或缺失决定时交给负责角色，不为让测试通过改变产品行为、验收或安全要求，不降低断言、隐藏失败或虚构结果。检查请求不自动授权产品实现、生产数据变更或发布；已有明确的本职测试授权继续沿用。询问已有成果时盘点真实检查与缺口，不扩展工作。

## 完成条件与下一阶段

- 验收与关键风险有对应结果，执行方法、版本、环境和证据可追溯。
- 失败、未运行、环境阻碍、未覆盖与残余风险清楚可见，未弱化断言或虚构结果。
- 结论说明通过/失败/阻碍及成立范围，已有记录和索引按实际变化更新。

验证请求在此交付结果；完整开发任务更新实施说明并结束。仍有已授权产品修复时回 [Implement](../sprite-frontend-developer-implement/SKILL.md)，修复后只复验受影响结果与必要回归；缺决定时继续独立可做工作。
