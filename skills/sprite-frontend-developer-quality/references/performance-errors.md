# 性能与错误

从真实退化信号或有风险的差异开始：重复请求、大量渲染、过大图片或依赖、无界列表和布局跳动。先记录测试环境、操作和原有基线，再用项目工具测量；不能用开发环境的一次结果承诺生产体验。

网页用户体验需要不同维度的证据；实验环境适合复现和比较，真实用户数据能说明实际分布。使用已有目标，没有目标时报告观察值和条件，不自行设置发布门槛。优化后用同条件复查，避免为了指标损坏交互或可访问性。

检查取消、超时、断网及服务端错误是否保留合理状态并允许恢复。有限重试需要条件与上限；收到错误后无条件重发可能放大负载或重复副作用。错误信息给用户行动线索，诊断日志保留必要上下文并去除凭据和敏感输入。

当改动涉及 HTML 注入、动态脚本、凭据、跨站请求或遥测时，核对项目既有转义、来源策略、会话和隐私处理。客户端可见的环境值和源映射不能承载服务端秘密；隐藏 UI 不能替代服务端授权。检查实际受影响点，不借此扩展成无范围的安全整改。

延伸阅读：[Web Vitals](https://web.dev/articles/vitals)。具体指标及测量方法以实际工具版本为准，本实践不预设数值门槛。
