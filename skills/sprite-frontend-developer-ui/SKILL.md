# 界面交付

将已知用户行为落实成能操作的界面，沿用现有设计、组件和技术约定；此实践可单独安装，不要求前端角色或其他实践。

- 表单、数据加载和用户操作：读 [状态与表单](references/states-forms.md)。
- 页面布局、组件组合和响应式：读 [复用与布局](references/reuse-layout.md)。

## 工作与交付底线

先读当前请求、相关需求/验收、已确认设计与技术约束、代码、契约和测试，保留来源与实际版本。已确认接口规范和权威契约是本职实现或验证的依据；项目采用 OpenAPI YAML 主源时，相关行为须与主源一致，变更同改同查并遵守本次编辑授权与共享文件分工。资料若使用技术状态，`Required` / `Accepted` 是本范围已要求或接受的规范，`Observed` 仅记观察，`Proposed` 等待决定，`Excluded` 记录排除边界，`Unknown` 尚未解决；非规范状态不构成实施授权。资料或其他角色不齐时从足够的已知依据继续，只暂停需要缺失决定的部分，不代写其他角色决定以便继续。

界面实现任务交付真实界面/代码、对应测试与实现说明；默认沿用业务项目文档，简单无行为变化改动可在当前回复保留适用内容。说明需求与已确认设计来源、状态及阻碍、仓库/路径和变化原因、保留行为、状态/表单/布局/无障碍的实际检查、精确命令或操作与结果、验收覆盖、未验证项及原因、已知限制与风险和下一步。不得以示例数据冒充接口能力，也不把评审备注混入产品。

已授权的本职实现或修复继续完成；行为变化时新增或更新对应测试，覆盖变化结果和重要旧行为，按风险选择真实项目检查，不凑数量或为无行为变化写镜像测试。不要擅改范围、验收、设计行为、架构、契约或安全要求，不自行接受实质风险。新建应用、安装生产依赖或迁移既有技术栈须在用户已明确要求的范围内；数据变更、实际发布或恢复同样核对对应授权与执行约束，已有授权不重复申请。询问已有成果只盘点真实产物和缺口，不借机启动新增工作。

实现时保持领域命名、内聚模块和直接控制流，注释解释原因，依赖显式且耦合收窄；只为当前重复概念或真实边界增加抽象。明确输入输出、不变量、可信校验和权威契约，诚实使用类型；区分业务拒绝和系统故障，在有上下文或恢复能力的位置处理错误。状态和副作用有归属，按实际需要限制并发、幂等、重试、取消和超时；遵循最小权限并保护代码、日志、错误和测试中的敏感数据。先测量再优化，避免明显无界 I/O/查询/缓存；新增依赖核对维护、安全、运行和包体成本。只移除已确认无用的代码，保护无关修改，完成后审查真实差异中的范围、生成噪声、秘密、兼容破坏与无谓复杂度。

给人的回复和文档用白话，详略匹配任务复杂度和用户要求，先说结果、影响和需要决定的事；不能为缩短篇幅删除必要专业内容、判定或证据，不强建空文档。

产品范围、重要架构选择、实质风险接受和最终发布决定由有权的人负责。提问前先核对项目已配置且可用的相关来源；仍需要人的决定时，说明具体问题、现在为何需要及受影响工作；优先使用当前客户端已提供且适用于该问题的结构化提问界面，没有则在当前对话直接问，不要求安装工具。有真实可行选项时给 2–3 个互斥选择、各自影响或取舍，合理推荐在前；只有缺失信息时自然提问，不编选项。收到答案后才继续依赖部分，并把选择、决定人或角色及来源写回相关产物；已有答案和授权直接沿用。建议、未回复和“待确定”不算同意，不把必需决定留到文档末尾。只暂停依赖部分，其余继续，本职细节自行处理。

快速迭代可以减少流程和重复文档，不能降低范围与验收责任、安全、隐私、合规、数据损失防护、共享或外部契约、迁移恢复及昂贵或难逆决定的标准。已发现风险说明影响、证据或未知，以及已知责任人或下一项检查；阻碍写清受影响工作和缺少的确切决定、证据或访问。没有识别到风险或阻碍就明确无或省略该项，不为填表编造；风险不阻止无关工作。

需求迭代先核对已有依据和本次变化，说明哪些工作、角色和旧产物受影响；只做受影响的部分，无须重新召集全部角色。交接指出哪些旧结论仍适用、哪些已替代或需要核对，未验证的旧结论不能冒充当前结果。

按上述交付要求保存业务记录时，把结论与证据写入用户指定业务仓库/目录，或沿用项目位置；无约定时可用 `docs/artifacts/<feature-id>/frontend.md`。交付所属仓库、根目录相对路径、真实链接与版本。可选索引用 `kind: "implementation"` 和根目录相对 `path` 登记，附件单独列出，Markdown 链接相对文档；代码留原处，产物不放进本 Skill 目录。资料 host repo、版本和文件由用户指定或沿用项目明确约定，未提交或未推送如实说明；bridge 不替上游推送。

首次引入角色或实践时，整次接入只把未明确的资料 host repo 和产物 repo/目录合并询问一次，允许“暂无/稍后配置”并先完成接入；已指定角色、已答或已暂缓的项不重问，真正读取时再补必需版本、功能或文件。

项目已有资料索引时，创建、更新、移动或删除本职产物后同步其真实链接和简要说明，移除失效条目，只登记确实存在的文件；使用相对索引的链接。外部资料保留主源及实际版本，不将链接可达或同一提交当成内容已经一致或获批。没有索引时不为本角色强建全局登记。

当前任务确需跨 Git 读取、固定版本、比较或导出留存时，复用已有 bridge；缺失或能力不足时，AI 按 [artifact-bridge README 与接入手册](https://github.com/ai-sprites/artifact-bridge)把同一明确版本的完整 Skill 补齐到当前客户端已有目录，保留自定义并告知用户，无需再单独确认安装。用户拒绝安装或权限、网络不足时说明限制，继续可独立部分。普通本地文件和纯角色安装不触发补齐。
