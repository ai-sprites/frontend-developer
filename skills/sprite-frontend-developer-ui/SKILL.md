# 前端开发交付

将已确认的用户行为落实成可用界面，沿用现有设计、组件与技术约定。本 Skill 可独立使用，不要求安装角色、其他 Skill、技术目录或完整 SDLC。

## 开始工作

实施、修复或评审前，读 [完整工作方法](references/workflow.md)：按其中的本职步骤核对资料与授权、适用技术约束、共享文件分工、工程纪律、验证、决定写回、迭代和业务产物留存。仅咨询已有成果时，读取与本次问题有关部分，不启动额外实现。

- 表单、数据加载和用户操作：读 [状态与表单](references/states-forms.md)。
- 页面布局、组件组合和响应式：读 [复用与布局](references/reuse-layout.md)。

上述工作方法包含本职必要检查。`sprite-frontend-developer-quality` 是可选深化实践，按任务需要使用，缺少它不阻碍有依据的本职工作。

## 完整模板与工作顺序

1. 从已确认请求、相关代码与真实契约确定最小完整改动；先沿用已有来源、资料仓库、版本和产物位置。重要决定仍未明确时，按工作方法真实提问，收到答案并写回后再推进依赖部分；已答或已授权的不重复问。
2. 按下表选择和读取模板。三份文件各有用途，普通小变更不强制全部创建；开发范围填写 `frontend` 或当前明确扩展的实际范围。

| 模板 | 何时使用 | 填成什么 |
|---|---|---|
| [实施计划](assets/templates/implementation-plan.md) | 复杂、多步骤、有风险或跨重要区域/仓库，需要持久实施依据时，在改动前读取 | 目标、保留行为、实施顺序、仓库变更、验收、契约协调及风险决定 |
| [实施任务](assets/templates/implementation-tasks.md) | 清单能改善排序、并行分工或验收覆盖时读取 | 可执行任务、依赖、负责人分工相关信息与实际证据/阻碍 |
| [实施说明](assets/templates/implementation-notes.md) | 功能完成或受阻后需要交接时读取；简单小改动可在回复中覆盖适用内容 | 真实状态、变更及原因、采用决定、精确检查结果、限制、覆盖和后续验证 |

3. 按完整工作方法实施并检查最小完整结果，行为变化覆盖新结果和重要旧行为，运行已核实项目命令并审查真实差异。共享文件的单一编辑者与交接顺序在编辑前明确。
4. 更新实际计划/任务状态，将命令、结果和未验证项写入实施说明；交付代码和真实业务文档链接，不只给模板链接。

读取选中的完整模板后再填充；保留原章节和字段，填入真实业务信息。已有文档结构可继续沿用，但须覆盖模板中的适用内容；无关字段写无或不适用，不编造数据、负责人、批准或执行结果。Markdown 占位链接采用 `(<...>)`；业务产物中的链接必须替换为真实路径，不保留模板路径作为交付地址。

已有产物先读取并局部更新，保留仍有效的结论；说明替代了哪些旧依据，未重新验证的旧结果不能冒充当前证据。按工作方法将文件实际保存到用户指定或项目现有业务仓库/目录，给出真实链接、仓库、相对 Git 根路径和依据版本；不能保存时如实说明，不能声称已交付。产物不写进本 Skill 安装目录。维护项目已有索引，不为本任务强建全局登记；文件未提交或未推送就不能声称其他 Git 仓库已可读取。

需要的工作模板或引用缺失时，从 [本角色仓库](https://github.com/ai-sprites/frontend-developer) 的同一明确版本补齐完整 Skill（包括 `SKILL.md`、`references/` 与 `assets/`），保留用户自定义；不要编造简版冒充原模板。无法补齐时说明缺失与限制，继续有充分依据的独立部分。
