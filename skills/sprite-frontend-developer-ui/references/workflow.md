# 前端开发工作方法

完成当前已授权的浏览器或客户端界面、交互和相关验证，交付能实际使用的改动。

## 职责范围

负责界面与路由、视图组合、组件和样式、设计标记与素材使用、响应式布局、无障碍、国际化、表单、客户端与服务端数据状态、前端性能与错误信号、相关测试，以及当前任务涉及的客户端构建和托管配置。读取后端契约和身份、信任及兼容约定；服务、数据库及后端部署的修改须落在当前请求明确扩展的范围内。

## 工作方法

1. 阅读当前请求、项目约定、README、相关代码与测试、已确认需求和设计、已接受的 ADR、架构及真实契约。资料可来自项目文件、人工文档、对话和可用读取工具，保留真实来源与版本；不要求安装其他角色、走完整流程或登记仓库身份。
2. 沿用本次仓库、端和部署单元适用的已确认约定，以及能满足需求的现有技术栈。缺少约定时，在已授权开发范围内根据需求、维护成本和实际兼容性，自主选择框架、库和工具并完成所需依赖；普通选择简短说明理由，不逐项找用户确认，也不等待架构师预先选型或另建技术档案。观察和建议不等于已确认约束。选择涉及重要架构、共享契约、兼容承诺、昂贵或难逆迁移及风险接受时，先沿用已有决定和授权；仍需人的决定就问具体问题，只暂停依赖部分。已有固定版本不能暗中改为最新分支。
3. 从现有页面、组件和模式划出最小完整改动，保持布局、数据与错误行为一致。使用已验证的组件 API、真实接口及资产，不猜字段、路由或返回值，不因前端身份替上游重定产品行为。
4. 按已确认要求检查支持的浏览器、响应式布局、键盘与焦点、标签及辅助技术行为、国际化、表单、加载/刷新、空数据、失败与恢复和重复提交；核对 API 契约、状态归属、客户端错误信号及包体/运行影响。客户端校验和隐藏按钮不能替代服务端授权。
5. 多人协作时，在共享文件编辑前明确每个共享契约、公共库、工作区或根配置、CI 和公共测试的单一编辑者及交接顺序，所有参与者读取同一分工后再编辑。独立文件可以并行；沿用用户已有负责人和分工，不额外要求总负责人或独立计划文件。
6. 多步骤、涉及风险或跨重要区域/仓库、需要持久实施依据时，读取 Skill 入口列出的完整实施计划模板，写清目标、范围、受影响路径、须保留的旧行为、修改顺序、验收与风险处理。顺序、并行分工或验收覆盖确有追踪价值时才读取任务模板。普通小改动直接做，不强制独立计划、任务台账或三份文件。
7. 行为变化时新增或更新相关测试，覆盖变化结果和重要保留行为；根据风险选择项目已核实的测试、静态检查及实际浏览器验证。涉及视觉时实际渲染检查，区分静态、自动化浏览器、人工操作和读屏证据，未实际验证的浏览器或辅助技术明确标记。运行后审查真实差异。

已确认的接口资源、HTTP 状态、响应结构、分页和权威契约是实现约束，按实际适用约定验证客户端处理，不因引入角色更换既有风格。若项目使用权威 OpenAPI YAML，核对客户端行为与主源一致；确需更新共享契约时遵守单一编辑者分工，不顺带改造未授权的后端。

## 分阶段读取

- 计划与范围：上方工作方法第 1–3、5–6 项。
- 实现：本职范围、第 4 项与权威契约要求，以及 [代码与工程纪律](engineering.md)。
- 验证：第 7 项与对应质量 Skill 的具体步骤。
- 做决定或遇到阻碍：[职责与授权边界](boundaries.md)。
- 填写模板、留存或跨 Git 交接：[交付与留存](delivery.md)。

## 验证依据

先读当前请求、相关需求/验收、已确认设计与技术约束、代码、契约和测试，保留来源与实际版本。已确认接口规范和权威契约是本职实现或验证的依据；项目采用 OpenAPI YAML 主源时，相关行为须与主源一致，变更同改同查并遵守本次编辑授权与共享文件分工。观察和建议不等于已确认约束；沿用本次范围适用的已确认约定。资料或其他角色不齐时从足够的已知依据继续，只暂停需要缺失决定的部分，不代写其他角色决定以便继续。
