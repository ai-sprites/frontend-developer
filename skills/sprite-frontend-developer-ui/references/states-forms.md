# 状态与表单

划清 URL、服务端数据、局部输入和临时界面的归属。筛选或导航状态需要可分享和后退时再放入 URL；能从已有数据推导的值不重复存成另一份状态。服务端缓存的更新与失效沿用项目方法，不额外引入全局存储。

一次异步操作要分清初次加载、已有内容刷新、空结果和请求失败。刷新失败不一定需要抹掉已有内容；区分旧数据与没有数据。快速切换筛选或路由时，取消旧请求或阻止旧响应覆盖新结果，清理不再需要的副作用。

表单保留可读标签、必要帮助和可关联的字段错误。客户端校验用于及时反馈，服务端仍是信任边界。提交失败保留有效输入；重复点击、超时后重试和离开页面的行为依赖真实契约，不靠禁用按钮宣称后端已防重复。

例如保存资料时，状态可为编辑、提交中、成功和可恢复失败。先核对现有服务是否幂等，再决定重复请求处理；不知道保存结果的超时不能直接显示“保存失败，可放心再试”。待定的重复语义单独指出，不阻碍完善标签和已明确的字段校验。

以键盘完成输入、提交和错误修正，观察焦点和状态反馈；确认错误不是只靠颜色显示。既有组件能完成时优先使用，复杂自定义控件再查对应交互规范。

延伸阅读：[W3C 表单无障碍教程](https://www.w3.org/WAI/tutorials/forms/)。
