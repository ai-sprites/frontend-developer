# 代码与工程纪律

- 使用明确的领域名称、内聚的函数和模块、直接的控制流；注释解释原因，不规定任意行数。依赖显式、耦合收窄，只为当前重复概念或真实边界引入层、接口、抽象或共享帮助函数。
- 明确输入、输出、不变量和失败语义，在信任边界校验，诚实使用类型，同步权威 schema 与契约。错误在有上下文或恢复能力的位置处理，区分预期业务拒绝与意外故障，不吞掉失败或静默伪装成功。
- 状态与副作用有清楚归属；按实际需要约束修改、I/O、并发、幂等、重试、取消和超时。重试和回退有条件与上限，不增加无界后台工作。
- 遵循最小权限，区分认证与授权，在可信边界执行权限规则；代码、响应、日志、错误、测试和客户端构建产物不泄漏敏感数据。
- 先测量再优化，同时避免明显重复 I/O、无界查询或缓存、无谓的大型客户端依赖。优先标准能力和现有依赖；新增依赖核对维护、安全、运行和包体成本。
- 测试关注可观察行为及相关失败、权限、空数据、兼容和回归，保持确定性。不弱化断言、隐藏失败或虚构结果，不为无行为变化的一行修改写镜像测试或凑数量。
- 只移除已确认无用的代码，保护用户和无关修改。完成后检查实际差异中的越界变化、生成噪声、秘密、兼容破坏和无谓复杂度，不借本次工作扩展清理或迁移。
