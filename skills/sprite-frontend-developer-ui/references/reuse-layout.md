# 复用与布局

先找受影响路由、外壳、相似页面、组件、样式与主题，实际读取用法后再使用组件 API。复用顺序可从局部已验证模式到项目组件，再到基础组件组合；是否抽出新组件取决于当前重复概念，不靠行数或未来可能复用判断。

尺寸与布局使用项目已有约定，明确窄视口时什么换行、折叠或滚动。选能暴露当前布局问题的视口：例如长标签、较大文字、窄屏和实际内容密度，不为每个可能尺寸建一套设计。

检查 DOM 顺序是否符合阅读与操作顺序，视觉重排不能破坏键盘体验。导航、按钮、输入优先使用有对应语义的原生元素；新增自定义菜单、对话框等控件时才核对完整键盘与焦点规则。

长文案、翻译和不同日期金额格式会影响宽度与换行；沿用项目国际化方式，不把临时写死的文本当成最终接口。图像、图标和字体来自实际可用资产，必要文字替代应描述用户需要的信息。

真实渲染当前改动，检查溢出、遮挡、跳动、焦点可见性和主要动作能否完成。审阅备注留在工具标注层或说明里，不混进产品 DOM 或布局。新页面不要暗中加入“待确认”横幅、无功能按钮或依赖猜测的内容。

延伸阅读：[W3C 交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/)。按实际控件查阅，不要求应用所有模式或改写已验证组件。
